# REQUIREMENTS.md

> **Status note (2026-10-19):** each item says whether it is **implemented**, **in progress**, or **planned (#N)**. Owner: the familia maintainer.

## Overview
High-level requirements for the familia topology coordinator: the Linux orchestrator, Android (Termux) nodes, Windows nodes, and the SSH nexus.

**Hard requirement:** familia must fit and run well on devices about 15 years old (the reference is qodesh: Athlon II X2, x86-64-v1, no AVX, GeForce 8600 GT 256 MiB). Old-device lowram and non-AVX smoke test: planned ([#48](https://github.com/brianreborn/familia/issues/48)).

## Core
- **Nodes:** Linux orchestrator (implemented), Android/Termux node over key-only SSH (implemented: #14, #18; next phone round planned while the phones are out of range, #46), Windows node (implemented: one-click installer and `scripts/windows/start.bat`, #17).
- **Guardian / defender nodes (graph type `pentests`):** first-class node flavor beside coder/chat (see `docs/guardian-nodes.md`, `docs/pentest-models.md`). **Seatbelts on by default** for automation: validate → would-start → stop. Never fully exercise attack tools, live scans, exploits, or network probes in automated tests or PoCs.
  - **Tools double-disabled for launch-tests (required seatbelt):** every automated guardian launch-test MUST disable tools in **two independent ways** before any process starts. Acceptable pairs today: (1) empty `tools.allow: []` in both `graph.yaml` `pentests.*` and `scripts/guardian-role.json` (legacy `scripts/pentest-role.json`), and (2) `launch_test_only: true` so `with-fleet.sh` refuses tool-capable paths. Empty `scope.allow: []` is additional default-deny for appliances, not a substitute for the second tools disable. Never remove either disable for CI or smoke tests. Operator may widen seatbelts only via explicit graph edit + confirm (schema-enforced).
- **Commands:** `/local` and `/remote` routing (implemented in the pinned code-bootstraps-llama.cpp agent, not in this repo).
- **Declarative configuration:** models, runtimes and agents declared in `graph.yaml` and checked by `scripts/validate_graph.py` (implemented; see `docs/configuration-graph.md`).
- **Config contract:** every config file, its readers/writers and requirement IDs are in [docs/config/](docs/config/README.md); changes update it in the same PR (CONTRIBUTING.md, CFG-RULE-001).
- **Hugging Face metadata alignment (hard requirement; tracked in #120):** locate and follow the authoritative Hugging Face Hub metadata formats. Use Hugging Face's canonical vocabulary for model/task node types and fields wherever the semantics match; retain only the minimum justified familia-specific extensions for coordination concepts that HF does not represent. Maintain a source-cited mapping of the full graph vocabulary, prevent lossy import/export, and update schema, validation, docs, tests, and migration guidance together. Never guess or silently coerce metadata.
- **RAM safety:** keep a large reserve on small hosts; `reserve_ram_mib: 3072` on miryam (implemented; provisional guidance — see `docs/ram-safety.md`).
- **Agents use the graph harness:** hermes-agent runs only through `scripts/hermes.sh`, whose `context_length` equals the node's per-slot context and whose compression is on (implemented; #19, live compaction self-test planned #42). Stock `hermes` with `~/.hermes` is not supported.
- **Escalation:** a light node may escalate to heavier nodes (`escalates_to`, `escalation.mode` off/suggest/auto, default suggest). The system may suggest, never opens a cross-host edge without recorded consent (implemented behind `hermes.sh --escalate`; router hookup and live swap planned #39).
- **Measured, not guessed:** placements and tuning come from `registry/records.jsonl`; tuning uses a coarse binary search and says so in the record (implemented; docs/model-registry.md).
- **Pinned parts stay in step (R-sync):** every script that updates anything, or runs code from a pinned part, first brings every part in `pins.txt` to its pin together (`scripts/sync_pins.py`); updating familia itself syncs right after. Never discards local changes (it stops instead), never force-pushes. Adding or fetching a model does not sync (implemented; see MANUAL.md).
- **Real test-suite acceptance (hard requirement; #119; see docs/testing/task-suite-acceptance.md):** substantial features require an end-to-end test on the real integrated path with representative inputs; unit tests, schema validation, and a successful server load alone are insufficient. New or materially changed model configurations (family/architecture, runtime/backend, quantization, tokenizer/chat template/system prompt, context beyond the model card, or unusual sampling/tool settings) stay planned/experimental until they pass a fixed task suite for their intended role against a baseline on the same tasks. Define success criteria first and record exact model/runtime revisions, configuration and prompt/template hashes, suite revision, seed, host/platform, per-task outcomes, aggregate, and limitations. Run on each platform claimed for the feature where relevant: initially Ubuntu, Windows, FreeBSD, and Samsung Android/Termux. If no suitable suite exists, add a small fixed representative suite before promotion and document its limits. Pentest coverage remains launch-test-only; never run attack tools or live network probes in automated tests.
- **Security assessment mode (operator-only; #116):** `scripts/sec_assess.py` is an explicitly invoked, fail-closed path (confirm env + `--i-authorize-assessment` + exact allowlist + bounded window). Never called from `start.sh`, graph startup, or CI. Low mode reads local inventory/policy only (no sockets); detail mode emits a supervised plan and refuses network in the current build. Remediation is propose-only until human approval; apply is stubbed refuse-until-approved. Docs: `docs/security-assessment.md`. Unit tests: fixtures only (`tests/test_sec_assess.py`).
- **Unit tests:** Python tests cover the graph, registry, model database and escalation (implemented). They remain required but do not replace the real-suite acceptance requirement above. Shell syntax CI (`sh -n` / shellcheck) is not set up yet (only CodeQL runs).

## Model database (implemented: #51; see `docs/model-database.md`)
- **Full Hugging Face repo, pinned (implemented):** every model in use has an entry in `registry/models/<id>.json`, built by `scripts/model_db.py` from the *entire* upstream HF repo at a commit SHA (`scripts/hf_fetch.py`, stdlib urllib, `HF_TOKEN` honoured and never printed): model card, `config.json`, `generation_config.json`, tokenizer and chat-template files, license, and the base repo for third-party quants. Every fetched file is verified (LFS sha256 or git blob sha1); weights over 50 MB are listed with size and LFS sha256 but not downloaded. Snapshots live in `~/.local/share/gguf/hf-meta/ORG--NAME/<sha>/`. `scripts/model_db.py backfill` covers the code-bootstraps manifest, `graph.yaml`, registry records, local model dirs and the HF cache; `add-model.sh --fetch` does the same for new models.
- **Use all of it (implemented):** each entry records a field-by-field `descriptor` (HF API, card, config.json, GGUF, official GitHub README; precedence card > config.json > GGUF > GitHub, every conflict kept with its sources), the card's and GitHub's command-line examples verbatim (`card_commands`: file, line range, tool; llama.cpp lines parsed into flags against the pinned build's flag table, vLLM/SGLang/transformers/Ollama/curl examples translated and marked so, with what does not translate) and `required_params` (REQUIRED / RECOMMENDED / OPTIONAL, each with value, source and why_required). Curated decisions live in `registry/model-params.yaml`, each with a quote that is checked against the stored card. Per model: `docs/model-params.md` (generated: `scripts/model_db.py params-doc`).
- **Enforced at launch (implemented):** `validate_graph.py --args` (familia `scripts/serve.sh`, `scripts/hermes_harness.py`) emits every REQUIRED and RECOMMENDED parameter and fails when one is missing or conflicts: `--jinja`, `--chat-template-file` when the GGUF's template differs from the repo's and the repo's is chosen (sha256-checked), embedders' `--embeddings`/`--pooling`/`-ub`/`-b`, YaRN only when the card documents it and ctx exceeds the native window, stop tokens not marked end-of-generation. Every flag is checked against the pinned build (`registry/llama-builds/<build>.json`, read from llama.cpp's `common/arg.cpp` at the build's tag); an unsupported flag or architecture is a blocker, never dropped. RECOMMENDED values may be overridden only with `override_reasons`.
- **Fail loud (implemented):** `validate_graph.py` rejects a model without an entry or a pinned revision, and a node whose ctx, `sampling` or `card_set` differs from the card without `override_reasons` (each a written reason). Registry records carry `model.db_id` / `model.revision` where the match is unambiguous; the rest have `db_id: null` and a `db_note`.
- **Old hardware still wins (implemented):** stdlib only, no weights fetched; the 20 current entries' snapshots total about 353 MB.

## Benchmarks and perf runs
- **Validate parameter metadata before any model run (required, 2026-10-19):** read the GGUF header (architecture, context length, rope, tokenizer, chat template, `general.sampling.*`); a missing field is a CRITICAL error and the model is not run, unless the field and the default used are written in the log and the perf doc. Never fall back silently. Every run records its full command line and the effective values from the load log and the bench output (n_ctx, n_batch, n_ubatch, threads, cache types, flash-attn, load mode, sampling, seed), and every result in `docs/perf/` lists them. Enforced by the perf driver (`gguf_meta.py`, see docs/perf/2026-10-19-tuning-2.md).

## Android node
- Launch via `android_start.sh` with host, port and user from the graph / environment and key-based SSH (#18). Fleet helpers `with-fleet.sh` and `scripts/pentest-role.json` are on `main` (fixes #15); pentest role remains launch-test only.
- `watchdog_android.sh` monitoring (implemented): key-only SSH, target from the graph, runs from its own directory and logs to `watchdog_android.log` there.

## SSH nexus
- Declarative config in the graph (`hosts` / `meshes`), key-only auth, password auth disabled (implemented as an opt-in proof of concept: `scripts/nexus/nexus.py`, docs/transport-poc.md).
- Letting nodes behind NAT talk through an edge host with `ssh -R` / `-L`: future, not planned yet.
