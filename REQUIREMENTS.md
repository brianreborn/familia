# REQUIREMENTS.md

## Overview
This document captures the high‑level functional and non‑functional requirements for the Green‑Roomz swarm system, including the Android pentest node, script regeneration, and the future SSH Proxy Nexus.

## Core Swarm Requirements
- **Nodes**: Linux orchestrator, Windows node, Android node (SSH on port 8022).
- **Node Type**: Use generic `task` node with metadata `role=pentest` for specialist reasoning; avoid creating new node ontologies.
- **Commands**: Support `/local` and `/remote` command routing.
- **Fleet Hand‑off**: All fleet operations must create a GitHub Issue (via `scripts/github_issue.sh`).
- **Regression Tests**: Provide end‑to‑end test suite for all scripts and tools.

## Script Regeneration
- Top‑level install scripts (`install.sh`, `start.sh`, `android_start.sh`) and any PowerShell equivalents (`*.ps1`) must be regenerated automatically when underlying tooling changes.
- Provide a `rebuild_top_level_scripts.sh` helper that:
  1. Reads a manifest of script templates.
  2. Emits concrete scripts in the repository root.
  3. Marks scripts executable.

## Android Node Integration
- Launch via `android_start.sh` using `sshpass` and register with `with‑fleet.sh --role pentest --manifest scripts/pentest‑role.json`.
- Monitor health with `watchdog_android.sh`; it should auto‑restart the node if unresponsive.

## SSH Proxy Nexus (Future Feature)
- **Goal**: Enable nodes behind NAT/firewalls to communicate via a public edge proxy.
- **Bidirectional Tunnels**: Use `ssh -R`/`-L` for reverse/forward tunnels.
- **Auth**: Centralized public‑key auth, optional OTP.
- **Scalability**: Support dozens of concurrent tunnels, expose `/metrics`.
- **Security**: Strong ciphers, disable password auth, optional 2FA.
- **Config**: Declarative manifest `proxy‑nexus‑config.json`.
- **Failover**: Secondary nexus host for high availability.

## Non‑Functional Requirements
- **Reliability**: 99.9 % uptime for the orchestrator and proxy services.
- **Observability**: Logs, metrics, and alerts for tunnel health and node status.
- **Security**: Zero‑trust networking, encrypted communication, audit logs.
- **Documentation**: Keep `MANUAL.md`, `LESSONS-LEARNED.md`, and this `REQUIREMENTS.md` up‑to‑date.
