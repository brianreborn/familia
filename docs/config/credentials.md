|---|---|---|---|

| CFG-CRED-008 | Secret files are referenced as `*_file: PATH` (mode 0600, outside the repo) where a tool needs a file rather than env | SPEC | — |
| CFG-CRED-009 | Any service listening on the network requires an API key by default. Localhost-only without a key is allowed only for named local-development-tool exceptions listed in DESIGN.md Security (each with a reason). familia llama-server and graph_router launches are not exceptions: `--api-key-file` from an owner-readable, not group- or world-readable file (mode 0600 or 0400) is required on every bind, including loopback. The key is never in graph.yaml. `scripts/bind_auth_guard.py` refuses a llama-server launch argv that would bind without a key. Two on-disk layouts exist and are not migrated yet ([#419](https://github.com/brianreborn/familia/issues/419)): canonical for graph-launched nodes is `instances/<port>/api-keys`; `familia-start` uses `~/.config/familia/api.key`. Clients accept `API_KEY_FILE` or `FAMILIA_API_KEY_FILE`. Known gaps (not exceptions): `scripts/escalation_proxy.py` is an unauthenticated loopback listener that injects the instance key into requests that arrived with none ([#415](https://github.com/brianreborn/familia/issues/415)); `scripts/bt/tracker.py` binds a LAN address with no key ([#416](https://github.com/brianreborn/familia/issues/416)) | PARTIAL | bind_auth_guard.py; validate_graph.py launch_auth_argv; DESIGN.md Security; #415; #416; #419 |
