# familia v0.4.0 release notes

- Version: 0.4.0
- Status: in progress (not released)
- Target date: not set yet

This is the current release target. The v0.3.0 notes stay at [v0.3.0.md](v0.3.0.md) as a draft of that earlier milestone.

## Scope (agreed)

Must land before the tag (no waivers; no known issues ship):

1. Pin coherence: keep `pins.txt` pointing at a real `code-bootstraps-llama.cpp` commit (see #604; do not pin a llama.cpp SHA on that repo).
2. Main CI green, including the swarm-pull test path (#605, folded into #604).
3. Integrate official [ggml-org/llama.cpp v1.0.0](https://github.com/ggml-org/llama.cpp/releases/tag/v1.0.0) (`b1b770d`) into `code-bootstraps-llama.cpp` (its `llama.cpp` submodule currently tracks `brianreborn/llama.cpp`, which has no `v1.0.0` tag), then re-pin familia to that new code-bootstraps commit.
4. Safe-mode / server tools: fix the launch-only `--tools` limitation ([#630](https://github.com/brianreborn/familia/issues/630)). No waiver.
5. LFM3-1.7B-Uncensored is the advertised default; either wire it as `nodes.coder` or keep the README honest about the miryam graph still using Qwen3.5-2B.
6. Version labels: README, ROADMAP, and these release notes should say v0.4.0, not v0.1.0-rc2 / v0.3.0 as the current target.

## Deferred

LFM3 VL/Omni/Audio as default nodes, BitTorrent transport beyond PoC, coordinator-free swarm, FreeBSD/macOS/AppImage installer depth, safe-build CPU node, SOUL glue, PQFreeBSD/green-roomz nexus audit, and the remaining v0.3.0 backlog.

## Platform verification

- **Linux:** the llama.cpp v1.0.0 pin (code-bootstraps `223bd358`, build `b12359`) is built and tested (CPU and Vulkan).
- **Windows / PowerShell: unverified.** qodesh and shalom were offline, so the `b12359` Windows archives (including CUDA 13.5) and the `.ps1` scripts are untested. `start.bat` F-6 gaps (#631): its own argv is ignored (exits 0, not 2), and a non-loopback `FAMILIA_BIND` with `--tools` in `FAMILIA_EXTRA` is not refused.
- **FreeBSD / macOS: untested** for the v1.0.0 pin.
